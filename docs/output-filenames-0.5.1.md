# 0.5.1 输出文件名与预检验收

日期：2026-10-06。分支：`codex/iteration-11-output-filenames`。提交：`fix(export): validate output paths during preflight`。版本与标签：`0.5.1` / `v0.5.1`。

## 复现与根因

1. 本机文件系统接受 249 个 ASCII 字符或 83 个中文字符加扩展名的原图。追加 `-frame` 后，输出路径检查返回 `File name too long (os error 36)`，但原预检仍然 `ready: true`。回归测试修复前明确失败。
2. 同名文件已经存在时，追加 `-2` 也可能让原本合法的长度溢出。
3. 真实 AppImage 的长英文文件名错误把摘要撑出可视区域，修正提示被裁切。初始浏览器断言只检查容器溢出，没有检查摘要边界；补上边界断言后复现失败。
4. 200 张原图全部缺失时，预检返回 200 条错误，绕过了原有 20 条限制。原因是提前 `continue`，没有执行循环底部的截断；回归测试修复前得到 200，预期 21（20 条与省略提示）。

根因是预检未调用实际输出路径选择逻辑。后缀字符数校验不能替代文件系统对完整路径和字节长度的限制。

## 修复

- 预检调用与实际导出相同的路径选择和重名检查，提前报告命名错误。
- 错误摘要允许长字符串换行，并设置最小宽度约束，防止被弹窗裁切。
- 无效或过长路径明确提示缩短原文件名、后缀或输出目录路径；保留原始系统错误供定位。
- 错误截断移至下一项开始前，覆盖原图缺失、尺寸读取失败和输出路径错误等提前退出分支。
- 保持「跳过重名」与禁止覆盖原图的行为。修改设置后清除旧预检错误，并再次预检后才开始导出。

## 边界

预检反映当时的文件系统状态。预检后出现的新文件或权限变化仍由实际写入的禁止覆盖和错误处理保护。不会静默截断用户的命名。文件名长度实测针对当前 Arch Linux 文件系统，未宣称跨平台限制相同。
