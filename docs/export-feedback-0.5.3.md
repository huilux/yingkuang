# 0.5.3 导出反馈体验验收

日期：2026-10-06。分支 `codex/iteration-13-export-feedback`，基于 `v0.5.2`。提交 `fix(export): keep progress and result controls readable`。版本与标签 `0.5.3` / `v0.5.3`。

真实 AppImage 的长文件名曾把进度「1 / 1」压成三行。浏览器回归复现了同类情况：249 个 ASCII 字符的文件名使「100 / 200」换行。计数的 flex 项允许缩小，而文件名占据剩余空间，缺少对两者的宽度约束。

结果弹窗同时存在两处体验问题：长文件名的横向内容达到 1447px，可视列表只有 476px；取消说明、大量失败和提示一起出现时，弹窗超出 1100×720 窗口的边界。原来错误和提示各有一个内部滚动框，正文没有统一高度限制。

本轮处理如下：

- 进度计数保持一行，文件名使用剩余空间并省略显示，悬停可读完整名称；阶段、计数和操作说明提高到 12px。
- 进度条使用应用的强调色，并提供「已处理照片」的可访问名称。
- 结果弹窗受窗口高度约束，正文统一滚动；标题和底部关闭、重试、打开目录按钮保持可见。
- 失败、提示分组可折叠，并标明项数；长名称、原因和路径自动换行。
- 失败项目显示原图路径，来自不同目录的同名照片可以识别；每条结果有独立的渲染标识。
- 保留取消未处理数量、实际耗时、原任务快照和失败项重试行为。

验收使用 200 条模拟照片记录，在 1100×720 运行真实界面。进度为 100/200；取消后成功 80、失败 110、未处理 10，另有 20 条长提示。验证计数一行、窗口边界、固定按钮、110 条失败完整保留、最后提示可达、分组折叠、原图路径可见，以及重试只提交原 110 个失败路径。

Chromium 新流程通过；WebKitGTK 新流程、原有完成/取消/失败计时和失败项重试通过。31 项前端功能检查、生产构建和入口预算通过。最小窗口浅色与暗色目视检查通过；进度及结果弹窗 axe 检查零违规、零待定项。

证据位于忽略目录 `test-output/audit/`：`webkit-0.5.3.jsonl`、`build-0.5.3.log`、`export-progress-a11y.json`、`export-result-a11y.json`、`screenshots/export-*-min.png`。200 条记录使用 IPC 模拟，证明反馈与重试交互，不代表真实导出性能。

0.5.3 AppImage 构建成功，并在独立配置目录、Xvfb 和 D-Bus 会话中恢复上一版照片与编辑。真实窗口缩为 1100×720：82 项实际元数据及常用参数可搜索，End 到达最后的自定义文字，Enter 添加一次，撤销恢复；长文件名导出时「1 / 1」保持一行，完成按钮可见。

使用 6000×4000 原片的长文件名副本，PNG 原尺寸导出显示处理用时 3 秒。实际成品为 6640×4800、29,773,509 字节，完整解码通过，ICC 588 字节、EXIF 326 字节，253 字节基础名称重名后生成 255 字节的 `-2.png`。原片与副本 SHA-256 一致。该次 UI 耗时是单次安装包检查，不替代第一轮重复性能测量。

原生证据：`test-output/appimage-0.5.3.log`，以及 `test-output/native-smoke/parameter-picker-*-0.5.3.png`、`export-progress-min-0.5.3.png`、`export-result-min-0.5.3.png`。尚未在干净系统验证 AppImage 的桌面双击运行。
