# 正式第一版范围

更新：2026-09-21。用户要求先完成可用第一版，再增加额外功能。本文约束正式应用的开发范围；当前 HTML 原型并未实现这里的完整导出流程。

## 已确认的开发决策

用户已确认以下三项按建议实施。其他既定需求继续有效。

| 项目 | 已确认方案 | 影响 |
| --- | --- | --- |
| 关闭应用后的本批工作 | 自动恢复上次照片列表与单张调整，暂不做多项目管理 | 持久化当前批次状态、原图引用和手动值；原图移动后提示重新定位 |
| 品牌/签名图片 | 首版先做文字水印，图片 Logo 后续增加 | 首版不加入图片 Logo 图层与复杂素材管理 |
| 输出色域 | 首版正确转换到 sRGB；广色域输出后续增加 | 渲染与编码需验证正确的色彩转换 |

用户的常见批次为 200 张，通常单张不超过 3000 万像素，也包含 9600 万像素照片。验收基准更新为 200 张混合横竖照片，包含 9600 万像素输入及加框后更大的成品。按解码后的像素内存预算限制并发，大图允许单张顺序处理，不能同时完整解码整批照片。预览使用缩小图，最终导出使用原图；上述规模是验收目标，不是导入硬限制或尚未测量的性能承诺。

无需用户决定技术栈、渲染缓存、元数据工具、数据库或线程数量。实现前由开发验证 Arch 环境中的字体、图像效果、原尺寸导出和元数据读写。应用名称、图标、发布渠道与许可证在公开发布前另定，不阻塞本地第一版开发。

其余建议默认：完全本地处理；JPEG 92；主照片保持原像素；基础拍摄信息保留、GPS 关闭；文件重名自动编号；缺失水印字段可手填，未填写时预览提示、导出省略该字段；混合横竖优先使用对应布局，无对应布局时适配并提示检查。上述默认值可修改，无需单独进行一轮决策。

## 第一版主流程

在 Arch Linux 桌面导入 JPEG/PNG → 选择相框模板 → 编辑水印和四边布局 → 将样式应用到横竖混合照片 → 检查 → 设置导出参数 → 批量导出成品。

必须具备：

- 模糊背景和纯色相框，照片保持比例，阴影柔和自然。
- 独立横纵基础留白，四边参数区，水印自由拖动与清楚的居中/三等分吸附提示。
- 元数据字段添加、缺失值补填、文字字体/字号/颜色/方向调整，实时预览。
- 缩放、滚动和平移；撤销与重做。
- 内置模板更新、另存新模板、横竖布局保存、本地持久化和可更新封面。
- 自动恢复上次照片列表、单张布局及手动参数；暂不提供多项目管理。
- 批量套用样式时保留每张照片自己的元数据与手动显示值。
- 从原始图片生成真正的批量成品，支持下述导出设置及队列反馈。

## 模板中的照片与封面

模板保存可复用的相框、区域、字体、字段绑定及布局。模板封面是用于识别模板的成品缩略图，不能作为批量渲染的主照片。

- 用户可以选另一张照片，套用模板并调整，再“更新当前模板”；当前方向的封面使用这张照片重新生成，另一方向布局和封面保留。
- 另存新模板生成独立封面；封面包括真实相框、水印和当前照片，省略辅助线、选框等编辑提示。
- 套用模板始终使用目标照片；EXIF 字段读取目标照片的值。更换模板封面不改变原图，也不把示例参数绑定给整批照片。
- 正式应用将小尺寸封面存为应用管理的资源，避免依赖示例原图路径或临时文件。原型使用本地存储中的 JPEG 缩略图，仅用于验证流程。
- 暂不新增独立封面编辑器；通过现有“更新模板”完成替换。

## 批量导出设置

以下选项纳入第一版；表中默认值是实施建议，可在开发时调整。

| 设置 | 第一版行为 | 建议默认 |
| --- | --- | --- |
| 导出范围 | 当前照片、选中照片、全部照片，显示数量 | 选中照片 |
| 输出格式 | JPEG、PNG | JPEG |
| 图片质量 | JPEG 提供 1–100 质量；PNG 无损，不显示有损质量滑块 | JPEG 92 |
| PNG 压缩 | 压缩等级，影响体积和耗时，不降低像素质量 | 标准 |
| 成品尺寸 | 保持原照片像素，或指定最终成品长边；可限制不放大小图 | 保持原照片像素 |
| 输出位置 | 本地目录，记住上次选择 | 使用上次目录 |
| 文件命名 | 原文件名加后缀，可加入序号；预览几个输出名称 | 原名 + `-相框` |
| 重名处理 | 自动编号或跳过；第一版不覆盖源文件 | 自动编号 |
| 元数据 | 不保留、基础拍摄信息、尽可能保留受支持信息 | 基础拍摄信息 |
| GPS 位置 | 独立控制，仅在保留元数据时启用 | 关闭 |
| 色彩 | 第一版统一输出 sRGB 并写入正确色彩标识 | sRGB |

“保持原照片像素”是指主照片区域不缩小，再向外加相框，所以最终成品可能大于原图。指定长边指含相框的最终输出尺寸。设置面板应显示当前样例的最终宽高，避免“原尺寸”的歧义。

输出位置在导出面板中显示为明确的文件夹路径，并提供“选择文件夹”。首次导出需要选择目录，此后预填上次选择且始终可改。同一批不同来源目录的照片集中输出到本次选定目录；完成后提供“打开输出文件夹”。目录不可写或不存在时在启动队列前提示重新选择，不静默改存到别处。默认成品文件名例如 `PANA9448-相框.jpg`，重名追加编号，保护源文件。

元数据导出与画面上的水印是两件事。不保留元数据，不会移除用户已经添加到图片中的拍摄参数文字；手动补填默认只修改水印显示值，不伪造写回源 EXIF。

基础拍摄信息使用明确白名单，例如相机/镜头、焦距、光圈、快门、ISO、拍摄时间。尽可能保留模式处理编码器支持的 EXIF/XMP/IPTC 字段，不能直接把原数据块原封不动附回输出：尺寸、方向、嵌入缩略图必须对应成品，旧缩略图应重建或移除。GPS 开关覆盖各类可写元数据中的定位字段；未经验证的整块厂商私有数据不盲目复制。无法保留的字段要在结果中说明。

ICC/色彩标识按实际输出处理，与是否保留拍摄元数据分别管理。首版不承诺广色域原样保留；如输入包含色彩配置，需先进行正确转换再标记为 sRGB，不能只改标签。

## 导出过程与验收

- 导出前冻结本次照片列表、样式和导出选项，避免任务进行中编辑影响尚未处理的文件。
- 先检查目标目录、重名、图片和字体可读取；提示缺失参数或布局越界，用户可返回对应照片调整。
- 队列显示总进度、当前文件、成功/失败/跳过数量。支持取消后续任务，保留已完成结果；单张失败不终止整批，可重试失败项。
- 按需解码、限制并发，逐张释放渲染资源。文件先写临时结果，再安全完成命名；取消或失败不能留下假成功的残缺文件。
- 结果页可打开输出目录。预览图与原尺寸导出共享布局规则和效果定义，辅助线/选中状态永不进入成品。
- 验收覆盖 JPEG/PNG、横竖混合、不同分辨率、EXIF 方向、缺失字段、同名文件、取消/重试、元数据/GPS 开关以及预览与导出位置一致性。

## 暂缓功能

不在第一版继续增加新相框类型、纹理/装饰框、自动行列分组、中文逐字竖排、模板市场、云同步或独立封面编辑器。其他额外需求进入后续列表，不阻挡主流程交付。上次工作恢复已确认；多项目管理、可移植项目打包及复杂素材管理延后。

技术栈和 Arch 打包方式仍待实现前验证。下一阶段优先打通原图读取、单张高质量导出及元数据处理，再接批量队列和桌面界面；不能用当前 1800 像素浏览器预览导出替代正式能力。
