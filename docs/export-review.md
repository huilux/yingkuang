# 导出功能审查与重构

日期：2026-09-24。范围：导出设置、预检、队列反馈、Rust 渲染与批量资源复用。

## 审查结论

| 问题 | 用户影响 | 本次处理 |
| --- | --- | --- |
| 浏览器原生 `min/max` 已判定长边无效，但开始按钮仍可提交 | `0`、小数或超大尺寸会进入后端；错误出现得太晚 | 抽出 `buildExportPlan`，统一冻结范围、文档和覆盖值，并在提交前校验范围、目录、长边、质量和文件名后缀 |
| 后缀可以包含 `/`、`\` 等路径字符，空后缀又被后端偷偷改回 `-相框` | 存在越出输出目录或生成非法路径的风险；界面示例与实际文件名不一致 | 前后端都拒绝路径/系统保留字符；空后缀保持为空；后端仍保证不覆盖原图 |
| 没有真正的导出前检查 | 源文件失效、目录不可写和超大输出要到队列运行后才暴露 | 新增 `preflight_export`：检查目录可写、源文件存在且能读尺寸、EXIF 方向和实际成品像素；大于 8000 万像素的单张成品给出内存提示 |
| 设置平铺在单列中，小窗口时关键的元数据和摘要被折叠到首屏外 | 批量范围、隐私选项和结果预估难以同时确认 | 设置按“位置与范围 / 文件与尺寸 / 隐私与元数据”分组；右侧固定摘要显示数量、文件名、尺寸和预计像素；底部操作始终可见 |
| 打开弹窗后焦点仍留在页面后方，Escape 不关闭，弹窗 `<header>` 造成重复 banner landmark | 键盘用户容易失去上下文，自动可访问性检查失败 | 焦点进入弹窗、Tab 留在弹窗内、Escape 关闭并把焦点还给触发按钮；改用普通语义容器。更新后 axe：0 violation / 0 incomplete |
| `current` 同时表示“当前照片”和“已完成照片”，阶段字段未显示 | 第一张处理时显示 `0 / N`，进度条会把正在处理误当成已完成 | 事件增加 `completed`，`current` 从 1 开始；界面显示准备、渲染、编码、元数据、收尾阶段；重复取消会被禁用 |
| 每张照片重新运行字体发现并加载字体 | 200 张批次会重复 `fc-match` 和读取同一字体文件 | 字体缓存提升为整个导出任务共享，任务结束后统一释放 |
| 指定较小长边时，同一张 24MP 原图分别为照片主体和模糊背景做全尺寸缩放 | 单张导出绝大多数时间耗在两次缩放 | 先生成一次目标照片；大比例缩小使用 Triangle，接近原尺寸/放大继续使用 Lanczos3；模糊背景复用目标照片，不再从原图重复缩放 |

## 性能实测

测试对象为仓库真实 `6000 × 4000` JPEG，导出 JPEG 长边 1200px，包含模糊背景、文字和基础 EXIF。命令使用 dev/test 构建，编译完成后单独计时：

```bash
/usr/bin/time -v cargo test --manifest-path src-tauri/Cargo.toml --lib \
  exports_real_jpeg_with_text_and_basic_metadata -- --nocapture
```

| 版本 | 测试内部耗时 | 进程墙钟时间 | 峰值常驻内存 |
| --- | ---: | ---: | ---: |
| 重构前 | 15.51 s | 15.92 s | 210,680 KB |
| 重构后 | 5.58 s | 5.79 s | 175,468 KB |

本机该样例墙钟时间减少约 **64%**，峰值常驻内存减少约 **17%**。这是单张指定长边场景的开发构建结果，不代表不同机器的固定承诺，也不能替代 200 张混合批次和 9600 万像素原尺寸导出的交付验收。

## 验证边界

- TypeScript 构建与导出计划单元测试覆盖范围冻结、失败项过滤、非法长边、危险后缀和空后缀。
- Rust 测试覆盖前后端同等硬校验、空后缀输出名、真实图片预检、实际 JPEG/ICC/EXIF 导出。
- Chromium 实际界面验证 1024×600 窗口、焦点进入与恢复、Escape、非法值阻止提交；弹窗 axe 检查为 0 项违规。
- 本轮 WebKitGTK/Xvfb 启动时在系统 GTK 层崩溃，未获得该引擎的新回归结果；对应回归脚本已经加入默认套件，环境恢复后可直接复测。
- 取消仍是“完成当前照片后停止后续照片”，不会强杀编码中的文件，以保证临时文件与输出文件的原子性。
