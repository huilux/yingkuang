# Konva 画布重构

日期：2026-09-21。范围为前端画布与交互状态，保留 Tauri/Rust 图像导入、原尺寸导出和版本 1 编辑文档。

## 实现

- `EditorCanvas.tsx` 使用 Konva / react-konva，视口尺寸固定。背景、水印、辅助线分成三个图层，背景与辅助层不参与命中检测。
- `canvas-camera.ts` 定义统一的平移/缩放变换、屏幕与文档坐标换算、适应视口和按屏幕像素计算的吸附阈值。缩放不会改变 DOM 尺寸，也不再读取并修正滚动条位置。
- React 保存已提交的文档；Konva 节点保存拖拽中的临时位置。松手调用一次 `onLayerCommit`，生成一个撤销步骤。Escape 或窗口失焦取消正在进行的拖拽。
- 缩放状态只回传到工作区工具栏，水印拖动期间不更新顶层 App，不序列化或持久化文档，不重绘背景。键盘微调和右侧对齐按钮仍可用。
- 文字选框采用 Konva 的实际文本尺寸，支持中文、字重、字体加载后的重新测量和旋转，不再按字符数量估算。
- `use-preview-backdrop.ts` 将模糊背景和照片阴影生成最长边 1600 像素的离屏 Canvas 位图；照片主体独立使用 `use-editor-photo.ts` 按需加载的最长边 4096px 编辑图，并由 Konva 裁切圆角。为兼容 WebKitGTK，滤镜仍通过离屏 SVG 计算，但不作为实时画布显示，也不再执行 PNG 编码后重新解码。参数输入合并 60ms，保留上一个可用预览，淘汰过期结果并释放临时 Blob URL。

多选与排版的后续补齐见 [原型功能对照](prototype-parity.md)。

## 操作

- Ctrl / Command + 滚轮：以鼠标位置为锚点缩放，支持细小触控板输入。
- 滚轮或双指滚动：平移；Shift + 纵向滚轮：水平平移。
- 空白区域拖动、空格 + 拖动、鼠标中键拖动：平移。
- 适应：重新居中并缩放到视口。
- 点击水印或右侧图层选择；画布聚焦时方向键微调，Shift + 方向键移动 10 个文档单位。
- Escape：取消正在进行的拖拽或平移。

缩放百分比沿用旧版预览基准，不代表原图像素的 1:1 显示。

## 验证

```bash
npm run build
npm run test:camera
npm run dev -- --host 127.0.0.1 --port 1422
# 在另一个终端运行：
xvfb-run -a python3 scripts/run-webkit-regressions.py http://127.0.0.1:1422
# 性能测量单独运行，避免并行测试干扰：
xvfb-run -a python3 scripts/run-webkit-regressions.py http://127.0.0.1:1422 zoom-performance.js
```

旧版依赖 SVG DOM、scrollLeft 和动态画布尺寸的回归脚本已由 `konva-canvas-regression.js` 与 `konva-test-utils.js` 替代。测试通过 DOM 鼠标、滚轮和输入事件驱动真实应用，通过 Konva 公共场景 API 观测坐标，不直接调用编辑器事件处理函数。

- 数学回归覆盖移动锚点、细小输入、横竖图适应与不同倍率下的吸附阈值。
- 交互回归覆盖视口尺寸/裁切、缩放范围、滑块往返、鼠标锚点、平移、背景缓存失效和快速参数回退、40%/100%/200%/300% 下的边缘抓取、快速松手撤销、取消、旋转、键盘、图层可见性及吸附。
- 桌面 IPC mock 回归使用竖图，验证拖拽期间 0 次会话写入、松手 1 次写入、一步撤销/重做，以及重新挂载后的恢复。原有浏览器导入、渐进导入和会话恢复检查保留。
- Chromium 真实鼠标：边缘按下后移动 1×1 像素，水印不移位；随后移动 24×12 像素，水印位移为 24×12 像素。真实中键平移 40×20 像素，画布平移量一致。
- WebKitGTK/Xvfb 开发页面的独立 48 帧往返缩放：首轮及重复轮中位数/P95 均为 17ms，无超过 32ms 的帧。重构前同环境记录为首轮中位数 27ms、P95 54ms。测量时背景缓存已生成，未计入首次图片解码和滤镜生成时间。

## 边界

上述帧耗时是本机虚拟显示环境的结果，不保证实体设备、不同 DPR 或触控板上的固定帧率。200 张批量与 9600 万像素内存验收仍待完成。

没有接入 libvips。后续的 [渲染质量修复](render-quality.md) 已统一原图解码、模糊颜色空间和阴影算法。前端 Canvas 文字与 Rust 字体渲染仍为两套实现，像素级一致性需要后续专项验证。画布重构不要求迁移已有模板或会话。
