# 原型功能对照与画布编辑补齐

更新：2026-09-24。依据 `prototypes/README.md` 与 `prototypes/editor-prototype.html` 中实际事件处理和排版算法核对，不把原型规划中的功能视为已经实现。

本轮优先补齐画布编辑；表中的后续项尚未实现，不代表已经全面达到原型功能对等。

## 本轮已补齐

| 功能 | 正式实现与规则 |
| --- | --- |
| Shift 点选多选 | 画布和图层列表均支持增选/取消；普通拖动已选成员保留整组 |
| 组合拖动 | 所选可见元素采用同一文档坐标位移，跨参数区仍保持相对距离；Escape 取消全部成员 |
| 组合选框 | 每个元素显示选框，多选显示整体边界；测量使用实际文字尺寸和旋转后的边界 |
| 横向等间距 | 至少三项，保留两端，按文字边界间隙分配；不是中心点等距 |
| 纵向等间距 | 按同一规则处理高度，作为正式编辑器补充 |
| 对齐参照 | 画布、照片、四边参数区及所属区域；对齐时整体平移，保持相对布局 |
| 元素间对齐 | 选择“所选元素”作为参照后，逐个元素对齐到共同边界/中心 |
| 三等分 | 上下区域按行对齐，左右区域按列对齐 |
| 批量样式 | 字体、字重、字号、颜色、透明度与旋转；混合值显示提示，内容保持各自元数据 |
| 批量区域归属 | 移入参数区时保持相对位置，整体移至目标中心；转为画布时保持全局位置 |
| 批量删除和撤销 | 一次操作仅产生一个文档提交与撤销步骤 |
| 精确 X/Y | 单选时输入区域百分比，Enter/失焦提交，Escape 放弃输入；支持超出区域边界 |
| 数字缩放 | 输入百分比，范围恢复为原型的 10%–300%；保留滑块与鼠标锚点 |
| 吸附补齐 | 画布、照片、区域与其他元素的中心/边缘，区域三等分；Ctrl/Command 拖动临时绕过；画布中心优先 |
| 快捷键 | Ctrl/Command+A 全选可见元素，Z 撤销，Shift+Z/Y 重做，Delete/Backspace 删除，方向键整组微调，Shift 加方向键移动 10 个文档单位；输入框内保留原生文本操作 |
| 恢复元数据原值 | 单选元数据字段可以清除当前照片的手动覆盖 |
| EXIF 字段与来源 | 添加参数包含原型常用字段、文件名和尺寸，并列出当前照片其余可读 EXIF 标签；菜单和选中图层均标明具体来源，动态字段随模板保存且参与原尺寸导出 |

和原型一致，区域坐标是布局依附关系，不是拖拽边界。对齐到照片中心时，底部区域的文字可以有负的局部 Y；其所属区域仍保留。不能对各元素分别钳制位置，否则组合会变形。最终输出仍裁切到成品画布。

隐藏图层可从列表选择并编辑样式，但不参与画布拖动与对齐。关闭或没有空间的参数区不能作为新的排版目标。原型没有框选，本轮也没有增加框选。

## 模块整理

- `selection-model.ts`：选择切换、组合位移、参照对齐和等间距分布；输入实际测量结果，返回批量文档补丁，不依赖 React/Konva。
- `EditorCanvas.tsx`：Konva 测量与交互，拖动期间只修改节点；开始拖动时缓存吸附候选，结束只提交一次。
- `LayerInspector.tsx`：图层列表、多选属性、对齐参照与精确定位面板。
- `EditorControls.tsx` / `NumericInput.tsx`：复用控件，补足滑块键盘事务和数值输入取消行为。
- App 统一应用批量补丁，过滤没有变化的补丁；不把选择状态保存进模板。
- 已移除只适用于旧单选实现的坐标钳制与吸附函数。

## 后续仍需补齐的原型差异

| 功能 | 剩余工作 |
| --- | --- |
| 固定成品比例 | 当前只跟随照片；需前端几何与 Rust 导出一并支持 |
| 本地字体导入与保存 | 当前仅提供常用系统字体；需字体资源管理、模板保存及导出字体解析 |
| 字距 | 当前文档和 Rust 导出还没有字距字段；需统一预览与导出度量 |
| 自动文字深浅配色 | 当前手动颜色；需持久化跟随规则及导出一致性 |
| 区域默认文字方向继承 | 当前支持逐元素旋转，尚未提供原型的“继承区域方向”编辑与导出语义 |
| 跳过已单独调整照片 | 需照片调整状态、批量应用选项与会话恢复支持 |
| 成品模板封面 | 当前封面仍使用照片缩略图；需生成含相框和水印、不含辅助线的封面 |

后续应按“文档模型 → 预览 → 原尺寸导出 → 旧模板兼容 → 回归”逐项完成，再评估 libvips 图片管线。不能只在前端增加控件而让导出忽略新参数。

## 验证

```bash
npm run build
npm run test:camera
npm run test:selection
npm run dev -- --host 127.0.0.1 --port 1422
# 另一个终端
xvfb-run -a python3 scripts/run-webkit-regressions.py http://127.0.0.1:1422
# 性能测量单独运行
xvfb-run -a python3 scripts/run-webkit-regressions.py http://127.0.0.1:1422 zoom-performance.js
```

- 数学测试验证不同文字宽高、保持两端的等间距、逐项与整体对齐区别、跨区域位移与选择切换。
- 浏览器测试通过 DOM 输入驱动真实应用：Shift 增减选、40%/100%/250% 组合拖拽、组合撤销/重做、等间距、照片参照对齐、批量样式、删除及快捷键。
- 精确输入回归覆盖坐标提交/取消、10% 数字缩放和 Ctrl 绕过吸附。
- 桌面 IPC mock 使用固定视口的竖图，验证三元素拖拽期间零次持久化、结束一次提交、一步撤销和重启恢复。原有导入、恢复与单选回归保留。

2026-09-21 验证结果：生产构建通过；相机 3 项、选择模型 6 项测试通过；WebKitGTK 完整 7 组回归通过，多选与精确输入也在 Chromium 中通过。WebKitGTK 缩放采样的首次/热缓存 P95 均为 17ms，各 48 帧中无超过 32ms 的帧。该结果是当前测试环境的采样，不代表所有硬件或图片规模。构建仍提示主 JS 包超过 500kB，后续可独立优化加载体积。
