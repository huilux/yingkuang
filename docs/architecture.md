# 正式应用架构

## 技术选择

- 桌面壳：Tauri 2。Arch Linux 使用系统 WebKitGTK，安装包优先提供 AppImage，并保留源码构建路径。
- 界面：React 19、TypeScript、Vite；交互画布使用 Konva / react-konva，固定视口加统一平移缩放变换。编辑器采用自有设计令牌和组件，不把营销页布局套入工作台。
- 图像与元数据：Rust 后端负责原图读取、方向归一化、高分辨率渲染、编码和元数据写入；前端保留列表缩略图、当前照片的高清编辑图和编辑状态。
- 状态：第一版使用版本化编辑文档，持久化上次批次、每张照片的手动参数、导出设置和模板。拖动过程只更新 Konva 节点的临时位置，结束时一次提交文档与撤销记录。视口变换独立于文档持久化。

## 模块边界

```text
UI shell
  ├─ Library: 导入、照片选择、模板
  ├─ Canvas: 预览、选择、拖动、吸附
  ├─ Inspector: 相框、区域、字段属性
  └─ Export: 设置、检查、队列、结果
          │ Tauri commands/events
Rust core
  ├─ catalog: 文件引用、缩略图、元数据
  ├─ layout: 与前端共享的版本化模板数据
  ├─ render: 原尺寸相框和文字合成
  ├─ metadata: EXIF/XMP/IPTC 读取与受控写入
  └─ export: 受限并发、取消、进度、原子写入
```

前端预览与 Rust 导出读取同一份版本化布局结构，并用几何测试约束关键位置。文字字号从 CSS em 换算到原生字体单位，跨 WebKit/Rust 回归比较普通与旋转文字的完整可见边界和中心。编辑画布只在有照片时加载；列表使用 720px 缩略图，照片主体按需加载最长边 4096px 的编辑图，与 1600px 的相框缓存分开绘制。导出队列顺序处理原图、逐张释放资源，模糊背景先在受限尺寸上生成后再放大，模糊在 linearRGB 下计算，阴影使用与预览相同的高斯遮罩，避免为大图创建额外全尺寸缓冲。

导出前端通过 `export-workflow.ts` 生成冻结的任务计划、输出预估和客户端问题列表；Rust 的 `preflight_export` 再以真实文件、EXIF 方向和目录权限复核。正式队列只接受通过相同后端硬校验的请求。单个队列共用字体缓存，指定较小长边时照片主体只缩放一次，模糊背景复用该目标图。问题、测量与验收边界见 [导出功能审查与重构](export-review.md)。

缩略图、高清编辑图和导出共用原生解码与颜色归一化。导出管线使用 Little CMS 将输入 ICC 转换到 sRGB，JPEG/PNG 均写入 sRGB ICC。EXIF 基础模式采用白名单复制，并重置方向和输出尺寸；“尽可能保留”仍会省略无法安全迁移的 MakerNote、旧缩略图、XMP/IPTC，并在结果页说明。

## 视觉方向

这是密集型摄影工具，不使用营销页常见的巨大标题、玻璃卡片或装饰动画。设计参数为 `DESIGN_VARIANCE 4 / MOTION_INTENSITY 3 / VISUAL_DENSITY 7`。界面使用冷中性色、单一鼠尾草绿强调色、8px 控件圆角和 12px 浮层圆角；阴影只表达照片和浮层层级。动效仅用于操作反馈和状态切换，并遵守减少动态效果设置。

画布模块、背景位图缓存、操作与回归命令见 [Konva 画布重构](konva-refactor.md)。

多选、批量排版与属性面板的模块划分，以及原型剩余差异，见 [原型功能对照](prototype-parity.md)。布局命令使用实际文字包围框计算，统一返回批量文档补丁；一次操作只提交一个撤销步骤。

高清预览与导出相框的一致性约定、复现数据和验证命令见 [渲染质量修复](render-quality.md)。
