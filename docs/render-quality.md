# 高清预览与相框导出一致性

日期：2026-09-22。

## 复现与原因

1. 列表和编辑画布共用最长边 720px 的缩略图，照片主体又被合入最长边 1600px 的相框缓存。放大缓存不会恢复原照片的细节。
2. 预览 SVG 滤镜默认在 linearRGB 下执行模糊和亮度调整；Rust 原先直接处理 sRGB 字节。同一色块输入的边框测试平均误差约 9.45、最大 31（每通道 0–255）。只统一颜色空间即可明显降低差异。
3. 预览使用高斯阴影，Rust 原先使用不同偏移、强度和衰减公式。阴影区域的独立测试平均误差约 29.35、最大 64。
4. Konva/浏览器把 `font-size` 当作 CSS em 尺寸，Rust `ab_glyph` 的 `PxScale` 却表示字体排版高度。把同一个数值直接传给两端，会令 32px 的中英混排文字从预览的 237px 宽缩到导出的 164px 宽。

滤镜颜色空间依据：[MDN color-interpolation-filters](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/color-interpolation-filters)。Rust 高斯模糊对线性光和预乘透明度的要求见 [image::imageops::blur](https://docs.rs/image/0.25.10/image/imageops/fn.blur.html)。

## 修复

- 列表继续使用 720px 缩略图；当前照片通过 `load_editor_photo` 从原文件生成最长边 4096px 的编辑图，小图不放大。PNG 传输保留透明度，导出始终独立读取原图，不受该预览尺寸限制。
- `use-editor-photo.ts` 先显示缩略图，再替换为高清图。只解码当前照片；原生高清解码串行执行，排队的过期请求不再解码；前端忽略过期响应。加载失败时保留缩略图并明确提示。
- 浏览器导入保留压缩 File，按需生成当前编辑图，不把整批原图同时解码并驻留。文件引用不进入模板或会话 JSON。
- `EditorCanvas` 将照片主体独立绘制，圆角裁切函数保持稳定引用。模糊背景和阴影仍使用受限的 1600px 缓存，拖动水印不触发照片背景重绘；缩放不重新解码原图。
- 缩略图、高清编辑图和导出共用原生 EXIF 方向处理与 ICC→sRGB 解码。
- 导出在预乘透明度的 linearRGB 浮点数据上执行模糊和亮度调整，转回 sRGB 后与相框底色、暗色叠层合成。预览显式声明相同滤镜颜色空间。
- 导出阴影改为高斯透明度遮罩，与预览统一偏移 `0.28 × shadow`、标准差 `0.42 × shadow`、不透明度 `min(0.4, shadow / 100)` 和颜色 `#070909`。工作遮罩最长边不超过 1800px。
- Rust 文字渲染按字体的 `units_per_em` 与排版高度换算 CSS 字号，并继续以图层中心为旋转中心。当前画布修改会直接进入导出请求；“应用到已选”复制当前编辑文档，不再重新读取可能过期的已保存模板。

缩放百分比仍是编辑器视口基准，100% 不代表原图像素 1:1。4096px 是编辑图上限；超大图片像素级检查仍需原图查看器。浏览器与 Rust 的抗锯齿像素可能略有差异，文字外框尺寸与中心位置由跨渲染器回归约束。

## 验证

```bash
npm run build
cargo test --manifest-path src-tauri/Cargo.toml --lib
npm run dev -- --host 127.0.0.1 --port 1422
# 保持开发服务器运行，在另一个终端执行：
xvfb-run -a python3 scripts/run-webkit-regressions.py http://127.0.0.1:1422
python3 scripts/render-parity.py
```

- Rust：8 项通过，2 项显式运行测试默认忽略；包含原图细线与 alpha 保留、透明背景合成、真实 JPEG/EXIF/ICC 导入与导出。渲染差异脚本会单独运行忽略的 fixture 生成测试。
- 最终 11 组 WebKitGTK 回归全部通过；生产构建、Clippy `-D warnings`、Rust 格式与 Git 差异检查通过。
- 3200px 两像素宽条纹经真实导入后逐像素保留；4000px 图片的列表为 720px，编辑图为 4000px。
- 原生 IPC 加载回归覆盖快速切换后的过期响应、重复渲染不重新读取、文件不可读的回退提示。
- WebKit/Rust 同输入的模糊区域平均误差约 1.81、最大 9；阴影平均误差约 0.45、最大 2。双倍导出尺寸缩回后，模糊区域平均误差约 1.81。浏览器滤镜内部量化和重采样会产生少量差异，不宣称完全逐像素相同。
- 32px 思源黑体中英混排文字在预览与导出中均为 237px 宽；可见高度相差 1px、中心相差约 1px。90° 旋转后的完整文字外框也通过同一误差阈值。
- 原生 UI 回归确认导出 IPC 收到最新文字、位置和字号；批量应用回归确认两张照片复制当前未保存画布，而不是活动模板的旧版本。
- 真实 6000×4000 照片生成 4096px 编辑图后，WebKitGTK 缩放采样首轮/热缓存 P95 均为 17ms，Chromium 约 16.8/16.7ms，每轮 48 帧均无超过 32ms 的帧。此采样不含首次解码，也不代表所有硬件。
- 真实照片的预览与 Rust 导出已进行并排视觉检查。200 张批量和 9600 万像素的峰值内存仍需独立验收。

原生代码有改动，开发环境需重启 `npm run tauri dev`；已经安装的应用需重新构建安装后生效。
